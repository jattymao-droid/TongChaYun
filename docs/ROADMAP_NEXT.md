# 通查云 后续能力规划

> 版本：v1.0 · 创建日期：2026-08-08  
> 定位：在 P0–P21 主流程已通的前提下，梳理**值得集成的下一阶段能力**，按价值与成本排序，便于排期。

---

## 0. 背景与原则

### 0.1 现状结论

查询发布、问卷设计与回收、统计导出、模板/渠道、Webhook、站内通知、仪表盘、协作管理员等核心能力已具备。下一阶段重点不应是「再堆题型」，而应是：

1. **运营闭环**（触达、预约、提醒）
2. **可信与可控**（版本回滚、风控、审批）
3. **对接扩展**（开放 API、多组织门户）

### 0.2 原则

| 原则 | 说明 |
| :--- | :--- |
| 场景优先 | 优先服务成绩查询、录取公示、报名回收、满意度调研 |
| 复用现有 | 站内通知、Webhook、起止时间、邮件配置、仪表盘等可直接外延 |
| 小步交付 | 每项可独立演示；先邮件/预约，再门户/开放平台 |
| 明确不做 | 完整 BI、原生 App、收费支付等暂不纳入默认路线 |

### 0.3 状态图例

`[ ]` 待做 · `[~]` 进行中 · `[x]` 已完成 · `[-]` 明确不做/暂缓

## 2. P22 — 触达与预约（优先）

### 2.1 目标

让运营者「发得准时、收得到信」，减少守在后台刷通知的成本。

### 2.2 任务清单

| ID | 项 | 说明 | 依赖 / 复用 | 验收标准 | 状态 |
| :--- | :--- | :--- | :--- | :--- | :---: |
| P22-1 | 预约发布 | 查询/问卷支持设定未来发布时间，到点自动 `status=已发布` | 现有 `start_time` / 定时任务（Quartz） | 设定 2 分钟后发布，到点短链可访问 | [x] |
| P22-2 | 自动截止 | 到达 `end_time` 自动停用或拒绝提交 | 现有截止时间字段 | 截止后公开页提示已结束且不可提交 | [x] |
| P22-3 | 到期提醒 | 截止前 N 小时站内通知（可选邮件） | `biz_survey_notify` / 邮件基础设置 | 管理员收到「即将截止」提醒 | [x] |
| P22-4 | 答卷邮件通知 | 新答卷除站内铃铛外，可发到项目负责人邮箱 | `biz_phase27` 邮件配置、Webhook | 提交答卷后邮箱收到摘要（可关） | [x] |
| P22-5 | 企微/群机器人 | 复用 Webhook，提供企微机器人配置向导与消息模板 | 现有 `webhook_url` | 文档 + 一键测试推送成功 | [x] |
| P22-6 | 发布成功触达 | 发布后可选：邮件自己 / 抄送同事链接与海报 | 发布接口 | 发布成功弹窗可选「发送通知」 | [x] |

### 2.3 设计要点

- 预约任务写入 `sys_job` 或业务表 `biz_schedule_task`，重启不丢。  
- 邮件模板与站点名/Logo 走基础设置，避免硬编码。  
- 通知默认关闭，项目级开关，防止邮件风暴。

### 2.4 完成标准

1. 可演示「预约发布 → 自动上线 → 截止停用」全链路  
2. 新答卷可同时站内 + 邮件（可配置）  
3. `./scripts/smoke_biz.sh` 主流程仍通过

### 3.1 目标

### 3.2 任务清单

| ID | 项 | 说明 | 验收标准 | 状态 |
| :--- | :--- | :--- | :--- | :---: |
| P23-1 | 查询数据版本 | Excel 覆盖导入前自动快照；支持回滚到上一版行数据 | 覆盖后可一键恢复覆盖前行数与样例 | [x] |
| P23-2 | 问卷设计版本 | 保存设计时保留最近 N 版 `questionsJson` 快照 | 设计页可查看/恢复历史版本 | [x] |
| P23-3 | 查询协作者 | 对齐 `biz_survey_admin`，新增查询协作表与权限 | 协作者可编辑不可删主项目（可配置） | [x] |

## 4. P24 — 风控与洞察

### 4.1 目标

在已有验证码、日限、疑似刷答基础上，形成可运营的防刷视图与转化洞察。

### 4.2 任务清单

| ID | 项 | 说明 | 验收标准 | 状态 |
| :--- | :--- | :--- | :--- | :---: |
| P24-1 | 风控看板 | 按 IP/设备聚合：提交量、耗时分布、无效率 | 问卷统计页或独立页可看 Top 异常 IP | [x] |
| P24-2 | 一键处置 | 标记无效、拉黑 IP/设备（项目级黑名单） | 拉黑后同 IP 提交被拒 | [x] |
| P24-3 | 公开页漏斗 | 浏览 → 开始填写/输入条件 → 提交 转化 | 仪表盘或统计页展示漏斗 | [x] |
| P24-4 | 渠道对比增强 | 渠道 UV、提交、转化并列 | 与现有渠道码数据打通 | [x] |

### 4.3 复用

访问日志 UV、`clientToken`、答卷 `costMs` / `validFlag`、渠道码。

## 8. 明确暂缓

| 项 | 原因 |
| :--- | :--- |
| 完整自助 BI / 拖拽报表 | 成本高，现有统计 + 导出已覆盖主场景 |
| 原生 App | H5 + 短链足够；维护成本高 |
| 在线支付报名 | 合规、对账、退款链路重，非默认教育公示场景 |
| FingerprintJS 等重指纹 | 隐私与依赖风险；现有轻量 deviceId 已够用 |
